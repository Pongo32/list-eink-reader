# Техническое задание: электронная читалка для Android 4

## 1. Назначение

Разработать простую автономную читалку для старого Android-устройства с экраном E-Ink. Пользователь открывает книгу или документ, после чего приложение само выбирает подходящий способ отображения и подготавливает страницы для комфортного чтения.

Основной принцип интерфейса — «магия»: минимум действий и настроек, отсутствие обязательной ручной конвертации и автоматическая фоновая обработка с лаконичной индикацией прогресса. Приложение должно оставаться отзывчивым на слабом устройстве.

Предполагаемый сценарий распространения первой версии — личное использование без публикации в магазине приложений.

## 2. Цели и границы проекта

### Цели

- Читать PDF и EPUB.
- Автоматически находить PDF- и EPUB-книги в доступных пользовательских каталогах и добавлять их в библиотеку без обязательного ручного импорта.
- Автоматически адаптировать PDF к экрану с помощью k2pdfopt, когда это улучшает читаемость.
- Сразу показывать документ, не ожидая завершения обработки.
- Запоминать позицию чтения и автоматически кешировать подготовленные страницы.
- Предусмотреть библиотеку с визуальным оформлением в духе раннего iBooks, адаптированным для E-Ink.

### Не входит в первую версию

- Облачная синхронизация, аккаунты и сетевые функции.
- Ручная настройка сложных параметров конвертации.
- OCR и распознавание текста, если они не понадобятся после прототипирования.
- Полноценная поддержка EPUB 3 и всех его интерактивных возможностей.
- DRM, магазин книг, словари, аннотации и заметки.
- Цветной интерфейс и обязательная поддержка цветных экранов.
- Анимация перелистывания страницы.

## 3. Целевая платформа и ограничения

- Целевое устройство: ONYX BOOX Faust 3 (2022); ADB подтверждает модель `MC_FAUST3`, Android 4.4.4 (API 19).
- Экран: 6″ E-Ink Carta, системный размер 758×1024 и системная плотность 240 dpi; чёрно-белый, сенсорный, с подсветкой MOON Light 2.
- ОЗУ: 512 МБ. Встроенное хранилище: 8 ГБ (по предоставленным данным доступно около 4 ГБ); есть microSD/microSDHC.
- Веб-макет используется только для проверки интерфейса на компьютере. Поддержка WASM во встроенном браузере Faust 3 не подтверждена и не является целевым runtime.
- Текущий APK собирается с `minSdk 19`; совместимость с более ранними Android не заявляется.
- Android 4.0–4.0.4 (API 14–15) не считается гарантированно поддерживаемой платформой до проверки выбранных версий MuPDF, NDK и бинарных компонентов.
- По предоставленным сведениям, SoC — Rockchip RK3128 (четыре ядра ARM Cortex-A7, 1,2 ГГц); `ro.hardware` сообщает `rk30board`.
- ADB подтвердил `ro.product.cpu.abi=armeabi-v7a`; это ABI целевого устройства. `arm64-v8a` не поддерживается.
- Предварительный диапазон NDK для проверки: r17c–r23; совместимость выбранной версии с целевым API необходимо подтвердить.
- Производительность и наличие API полного обновления E-Ink-экрана ещё не проверены.
- Для первичного прототипа предполагается доступ к файлам через файловую систему; системный Storage Access Framework доступен только на более новых версиях Android и не является обязательной зависимостью.
- PIE/non-PIE и запуск нативного k2pdfopt должны проверяться на фактической версии ОС и целевом устройстве, а не приниматься как универсальное свойство всех Android 4.x.

## 4. Поддерживаемые форматы

### Обязательные для первой версии

- PDF — просмотр и, при необходимости, автоматическая адаптация через k2pdfopt.
- EPUB — отображение с переверсткой под размер экрана через MuPDF.

### Кандидаты, требующие технической проверки

- DjVu — проверить совместимость с выбранной сборкой k2pdfopt и способом отображения результата.
- FB2, MOBI и CBZ — проверить поддержку в конкретной версии MuPDF до включения в список заявленных форматов.

Формат желательно определять по содержимому файла, а не только по его расширению. Для входящих файлов необходимо поддержать доступ по URI, в том числе через `ContentResolver`, если файл открыт из другого приложения.

## 5. Пользовательские сценарии

### 5.1 Открытие документа из файлового менеджера

1. Пользователь выбирает PDF или EPUB и открывает его в читалке через системное действие `ACTION_VIEW`.
2. Приложение проверяет доступность файла и определяет формат.
3. Первая доступная страница показывается как можно быстрее.
4. Позиция чтения восстанавливается, если документ уже открывался.
5. Для PDF в фоне определяется необходимость адаптации и запускается обработка, если она нужна.

### 5.2 Открытие документа из библиотеки

1. Пользователь выбирает книгу на полке библиотеки.
2. Приложение открывает документ и восстанавливает последнюю позицию.
3. Недавно открытые документы отображаются в библиотеке с названием и обложкой или стандартной заглушкой.

### 5.3 Автоматическая обработка PDF

1. Приложение оценивает размер страницы и читаемость исходного отображения на экране.
2. Если PDF удобно читать без преобразования, приложение показывает оригинал.
3. Если обнаружены листовой формат, несколько колонок или слишком мелкий текст, запускается k2pdfopt.
4. После появления первой страницы все исходные страницы PDF последовательно обрабатываются в фоне; индикатор показывает долю обработанных страниц.
5. Готовые обработанные страницы незаметно заменяют исходное отображение с сохранением позиции пользователя.
6. Если обработка недоступна или завершается ошибкой, исходный PDF остаётся доступен для чтения без уведомления о сбое конвертации. Если невозможно открыть сам исходный файл, пользователю показывается короткое понятное сообщение.

### 5.4 Чтение EPUB

- EPUB отображается через MuPDF с компоновкой под размер экрана.
- Позиция сохраняется как закладка/позиция движка, а не только как номер страницы.
- Флажок в правой части верхней панели открывает список закладок поверх страницы слева. В панели можно добавить или убрать закладку текущей страницы; выбор записи возвращает к сохранённому месту. Нажатие на флажок повторно или на свободное место закрывает панель.
- Нажатие на встроенное изображение EPUB открывает увеличенный просмотр изображения; нажатие по нему или свободному месту закрывает просмотр и возвращает к странице.
- Кнопки A- и A+ изменяют размер шрифта только в EPUB, перевёрстывают книгу и сохраняют размер отдельно для каждой книги.

## 6. Функциональные требования

### 6.1 Библиотека

- Показывает библиотеку документов с обложками; новая обложка может формироваться рендером первой страницы.
- Автоматически ищет и индексирует файлы PDF и EPUB в доступных пользовательских каталогах внутреннего и подключённого съёмного хранилища; ручной импорт для появления книги в библиотеке не требуется.
- Первичное сканирование и обновление библиотеки выполняются в фоне; изменения в отслеживаемых каталогах обнаруживаются через `FileObserver` или совместимый с целевым устройством механизм.
- Индексация не должна блокировать интерфейс или постоянно расходовать ресурсы. Конкретные каталоги и исключения, обнаружение подключённых носителей и необходимые разрешения уточняются на прототипе.
- Открытие документа из файлового менеджера поддерживается независимо от результатов индексации библиотеки.
- Поддерживает скевоморфное оформление, адаптированное к монохромному экрану.
- Обложки и названия не должны ухудшать контраст и читаемость.
- Необязательные визуальные эффекты не должны блокировать открытие книги.

### 6.2 Экран чтения

- Показывает страницу на максимально доступной полезной площади.
- Поддерживает листание аппаратными кнопками и нажатием на левую/правую область экрана.
- Не использует постоянные панели и анимацию перелистывания, мешающие чтению или обновлению E-Ink.
- Показывает временную панель закладок и увеличение изображения только по запросу пользователя.
- Автоматически и регулярно сохраняет прогресс чтения при перелистывании, а также при уходе приложения в фон или его штатном закрытии; сохранённое состояние не должно зависеть от наличия кеша.
- Поддерживает базовые состояния загрузки и ошибки; во время фоновой конвертации PDF показывает неподвижную заполненную точку и процент обработки, которые исчезают после завершения.

### 6.3 Позиция и идентификация документа

- Прогресс чтения хранится локально и отдельно для каждой книги: для PDF сохраняется текущая исходная страница с учётом перехода между оригиналом и адаптированными страницами, для EPUB — позиция движка/закладка, позволяющая продолжить чтение с близкого места.
- Пользовательские закладки хранятся отдельно от позиции продолжения чтения и списка закладок других книг.
- При повторном открытии книги приложение автоматически восстанавливает последнюю сохранённую позицию, в том числе после закрытия приложения или перезапуска устройства; если точное восстановление невозможно, открывается ближайшая доступная позиция.
- Сохранение прогресса не должно требовать ручного действия и не должно приводить к потере уже записанной позиции при внезапном завершении приложения.
- Настройки чтения хранятся локально.
- Для поиска сохранённого состояния используется стабильный идентификатор документа. Предпочтителен хэш содержимого; допустимый упрощённый вариант — хэш частей файла вместе с дополнительными атрибутами.
- При изменении размера шрифта или переверстке EPUB позиция должна восстанавливаться по закладке или близкой позиции движка.
- Для преобразованного PDF должна сохраняться связь исходных страниц с результатом, чтобы переход между оригиналом и обработанными страницами не сбрасывал чтение.

### 6.4 Кеш

- Временные результаты преобразования хранятся в кеше приложения.
- Кеш очищается автоматически по политике LRU или эквивалентному ограниченному механизму.
- Удаление кеша не должно удалять исходные книги или сохранённые позиции чтения.
- Размер кеша и поведение при нехватке места уточняются на этапе прототипа.

## 7. Архитектура и стек

### Android-приложение

- Java.
- Нативные `Activity` и `View`; не использовать AndroidX и AppCompat, если они несовместимы с целевыми версиями Android.
- Gradle и минимально необходимая конфигурация проекта.
- `SharedPreferences` для настроек и позиции чтения.
- `java.io.File` и системные URI/`ContentResolver` для доступа к документам.

### Обработка и отображение

- **MuPDF (JNI)** — основной движок отображения PDF и EPUB; поддерживаемые форматы и API необходимо подтвердить для выбранной версии.
- **k2pdfopt** — отдельный ARM-бинарник для адаптации PDF. Приложенный x86-64 ELF-бинарник пригоден только для экспериментов на Linux-ПК и не запускается на ARM-устройстве.
- Предпочтительный способ запуска k2pdfopt — отдельный процесс через `ProcessBuilder`; бинарник копируется из `assets` в приватный каталог приложения и получает необходимые права на запуск.
- **`IntentService`** либо другой совместимый с выбранным API фоновый исполнитель — обработка страниц без блокировки UI. Окончательный выбор проверить для целевой версии Android.
- Собственный `PageView` на Android `View`/`Canvas` — отображение страницы и минимальных элементов интерфейса.

### Поток обработки PDF

1. Получить входной документ и при необходимости скопировать его в приватное хранилище приложения.
2. Показать исходную страницу через MuPDF.
3. Определить параметры экрана из `DisplayMetrics`; при необходимости сверить правдоподобность DPI с моделью устройства, диагональю и доступным профилем.
4. Получить из MuPDF размер страницы, наличие текстового слоя и ориентировочную высоту символов; классифицировать документ как текстовый, скан или многоколоночный.
5. Выполнить пробную обработку 2–3 страниц и измерить скорость и качество.
6. При необходимости запустить k2pdfopt с параметрами ширины, высоты, DPI, глубины оттенков и режима.
7. Последовательно обрабатывать страницы всего документа, не блокируя чтение.
8. Сохранить результат в кеше и обновить соответствие страниц.
9. Передать готовые страницы в механизм отображения без потери позиции чтения.

Пример предполагаемой команды (флаги и формат выходных файлов необходимо сверить с `k2pdfopt -?` именно для целевой сборки):

```text
k2pdfopt in.pdf -ui- -x -w <ширина> -h <высота> -dpi <dpi> -mode def -col 2 -wrap+ -bpc 4 -ocr- -p 1-10 -o out_%s.pdf
```

Автонастройка после пробного прогона:

- Если обработка занимает более примерно 3 секунд на страницу, отключить необязательные дорогие режимы и снизить качество/разрешение до приемлемого уровня.
- Если количество страниц после переверстки в 3 и более раза превышает исходное, уменьшить размер текста (`-fs`) и повторить обработку тестовой порции.
- Пустые, повреждённые или визуально нечитаемые результаты не подменяют оригинал.
- Успешные параметры можно повторно использовать для документов того же класса (например, текст, скан, две колонки); параметры должны корректироваться при изменении устройства или результата проверки.
- Если проба показывает, что обработка не даёт заметного улучшения, продолжить чтение оригинала.

До фиксации MuPDF в роли рендерера результата проверить, может ли целевая сборка k2pdfopt выдавать страницы в формате изображений. Если да, сравнить этот вариант с PDF-результатом по размеру, скорости и качеству.

## 8. Требования к E-Ink и визуальному стилю

- Использовать ограниченную палитру примерно из 4–6 оттенков серого; учитывать, что устройство может отображать около 16 уровней серого.
- Не использовать плавные градиенты и тяжёлый дизеринг как обязательную часть интерфейса.
- Объём и фактуру передавать контрастными контурами, штрихами и небольшими повторяемыми текстурами.
- Для повторяемых фактур допускаются тайлы размером примерно 64×64–128×128 пикселей с глубиной 4 бита, повторяемые через `BitmapShader`; остальная графика рисуется на `Canvas`.
- Скевоморфизм преимущественно использовать в библиотеке: полка, корешки книг, обложки, умеренные тени.
- Экран чтения должен оставаться спокойным и высококонтрастным: без текстур под основным текстом.
- Декоративные элементы в режиме чтения ограничить рамкой, краями стопки страниц и статичной закладкой.
- Отключить анимации перелистывания. Допускается статичный визуальный индикатор перелистывания и один промежуточный кадр, если он не вызывает заметного мерцания.
- Предусмотреть настройку аппаратного ускорения на уровне приложения/экрана; проверить программный рендер на целевом устройстве.
- Статичные элементы интерфейса при необходимости кешировать в `Bitmap`.
- Для принудительного полного обновления экрана использовать только проверенный API конкретного производителя либо безопасный стандартный режим. Вендорские API не считать универсальными.
- До разработки UI подготовить HTML-макет библиотеки и экрана чтения в 16 оттенках серого и утвердить направление визуального стиля.

## 9. Производительность и память

- Первая страница должна открываться до окончания фоновой обработки документа.
- Не загружать весь документ в память для конвертации.
- Обрабатывать PDF по диапазонам страниц и кешировать результат.
- Удерживать в памяти не более 2–3 растровых страниц, если это позволяет движок.
- Для снижения расхода памяти проверить `Bitmap.Config.RGB_565` и рендер в оттенках серого.
- `android:largeHeap` допускается только после измерений; он не заменяет ограничение числа одновременно загруженных страниц.
- Проверить скорость на слабом ARM-процессоре, включая время обработки страницы и реакцию интерфейса.
- Выполнять фоновую конвертацию с низким приоритетом. Полную предварительную конвертацию больших книг, если она появится, выполнять только при зарядке устройства.
- `android:largeHeap` проверять на целевом устройстве как возможную настройку, а не использовать вместо ограничения памяти и количества `Bitmap`.

## 10. Размер приложения и сборка

- Собрать нативные компоненты для минимального числа ABI после проверки `getprop ro.product.cpu.abi` на Faust 3; до этого `abiFilters` не фиксировать.
- Проверить возможность исключить ненужные шрифты, JavaScript-движки, кодеки, OCR и прочие необязательные компоненты MuPDF.
- Использовать сжатие кода и ресурсов, если оно совместимо с выбранной конфигурацией сборки.
- После подтверждения ABI ограничить первую сборку через `abiFilters` только фактической архитектурой; исключить AndroidX и Kotlin stdlib, если они не нужны приложению.
- Проверить R8/ProGuard и сжатие ресурсов на совместимость с выбранной старой Android-сборкой.
- Для MuPDF проверить сборку без ненужных CJK-шрифтов, JavaScript-движка и кодеков; для k2pdfopt — без OCR и необязательной поддержки DjVu.
- `strip` и UPX можно оценить для ARM-бинарника только при обязательной проверке запуска и корректности результата на устройстве.
- Целевой размер APK порядка 6–10 МБ является предварительной оценкой, а не гарантированным требованием; подтвердить после первой сборки.
- Проверить размер и запуск ARM-бинарника k2pdfopt отдельно.
- Вопрос PIE/non-PIE и совместимости исполняемого файла проверить на фактической версии Android. Нельзя считать один вариант бинарника совместимым со всеми Android 4.x.

## 11. Безопасность и надёжность

- Обрабатывать ошибки чтения URI, отсутствующие файлы, нехватку места и ошибки запуска нативного процесса.
- Не удалять и не изменять исходный документ.
- Входные файлы и результаты обработки хранить раздельно.
- При сбое k2pdfopt сохранять возможность читать оригинал через MuPDF.
- Не показывать пользователю необработанные логи и системные пути.
- Ошибки фоновой конвертации не прерывают чтение и не требуют реакции пользователя: приложение молча оставляет оригинал.
- Не скрывать ошибки открытия, чтения или доступа к исходному документу: сообщать о них коротким понятным сообщением.

## 12. Лицензии

- k2pdfopt распространяется под GPLv3; распространение приложения с ним требует проверки обязанностей по распространению исходного кода и лицензий.
- MuPDF распространяется на условиях, которые могут требовать AGPL либо коммерческую лицензию Artifex для закрытого приложения.
- Для проверенной зависимости `com.artifex.mupdf:fitz:1.15.0` POM указывает AGPL-3.0; это относится к конкретной используемой версии и не снимает необходимости проверить условия перед распространением.
- До публикации необходимо зафиксировать версии библиотек, проверить тексты лицензий и определить модель распространения приложения.
- Лицензионную совместимость сочетания компонентов должен подтвердить ответственный за выпуск.

## 13. Этапы работ

Каждый следующий этап начинается после подтверждения результата предыдущего.

1. **Инвентаризация устройства:** версия Android, ABI/процессор, разрешение, DPI, объём RAM, модель E-Ink и доступность API обновления экрана.
2. **Проверка концепции нативной части:** собрать ARM-версию k2pdfopt и проверить запуск на реальном устройстве; открыть PDF и EPUB через выбранную версию MuPDF. Это главный технический риск и выполняется до основной разработки UI.
3. **Макет:** подготовить и согласовать HTML-макет библиотеки и экрана чтения в градациях серого.
4. **Минимальная читалка:** открытие файла, отображение страниц, листание кнопками/тапами, сохранение позиции.
5. **Автоматическая обработка:** пробный прогон и адаптация PDF порциями, кеширование, тихий откат и переход между оригинальными и подготовленными страницами.
6. **Библиотека:** индексирование документов, обложки, отслеживание новых файлов и E-Ink-адаптированный скевоморфный стиль.
7. **Оптимизация:** измерение памяти, скорости, размера APK, фоновой нагрузки и времени работы от батареи.
8. **Проверка перед выпуском:** тестирование на целевом устройстве и проверка лицензионных обязательств.

Минимальный тестовый набор: PDF в две колонки, отсканированный PDF, PDF формата A4 с мелким шрифтом и EPUB с иллюстрациями.

## 14. Критерии приёмки

- PDF и EPUB открываются на согласованной целевой версии Android и устройстве.
- Первая страница становится доступна до завершения полной фоновой обработки.
- При успешной адаптации PDF обработанные страницы появляются без потери позиции чтения.
- При сбое или невозможности конвертации исходный PDF остаётся читаемым.
- PDF- и EPUB-прогресс автоматически сохраняется и восстанавливается после закрытия и повторного открытия книги, в том числе после перезапуска устройства.
- Закладки книги сохраняются между запусками; выбор закладки открывает нужное место, а удаление закладки не меняет позицию чтения.
- Встроенное изображение EPUB можно открыть увеличенным и закрыть повторным нажатием.
- Размер шрифта EPUB можно увеличить и уменьшить; после перевёрстки текущая позиция чтения сохраняется, а настройка восстанавливается отдельно для каждой книги.
- Навигация работает аппаратными кнопками и нажатием по краям экрана.
- UI не блокируется во время обработки.
- Во время обработки всего PDF футер показывает неподвижную точку и процент обработанных исходных страниц; после 100% оба элемента скрываются. При ошибке чтение продолжается по оригиналу без сообщения о сбое конвертации.
- Библиотека индексирует согласованную область хранения в фоне, а открытие файла извне работает без предварительного индексирования.
- Интерфейс остаётся различимым на монохромном E-Ink-экране и не полагается на анимацию.
- Приложение не удаляет и не изменяет исходные файлы пользователя.
- Размер APK, время открытия, время обработки страницы и расход памяти измерены и зафиксированы для целевого устройства.

## 15. Открытые вопросы

Целевое устройство зафиксировано: ONYX BOOX Faust 3 (2022), Android 4.4.4/API 19, ABI `armeabi-v7a`, 6″ 758×1024 E-Ink, системная плотность 240 dpi, 512 МБ RAM. Для первой рабочей версии выбрано нативное Android-приложение; веб-версия остаётся прототипом интерфейса на компьютере.

APK с MuPDF `fitz` 1.15.0 и ARMv7-сборкой k2pdfopt установлен и запущен на Faust 3. На синтетическом EPUB проверены навигация, восстановление позиции, сохранение пользовательской закладки после перезапуска процесса и возврат по ней на страницу. Встроенное изображение синтетического EPUB открылось в увеличенном просмотре и закрылось нажатием. На синтетическом двухстраничном PDF проверены показ исходной страницы до завершения фоновой конвертации, создание PNG-кеша для обеих исходных страниц, переход между адаптированными страницами и восстановление позиции на части страницы после перезапуска приложения. Проверка выявила и исправила переопределение DPI источника в k2pdfopt; повторный прогон создал по пять адаптированных частей для каждой тестовой страницы. На синтетическом четырёхстраничном PDF проверено фоновое преобразование всей книги: процент прогресса менялся, навигация оставалась отзывчивой, а по завершении индикатор скрылся. В футере теперь используется неподвижная точка вместо вращающегося индикатора. Длинные названия на обложке полки теперь ограничены тремя строками с многоточием.

Это только синтетические smoke-тесты; личные книги не открывались. Качество на реальных PDF (включая сканы, колонки, иллюстрации и сложную разметку), измерения скорости/памяти/батареи, физические клавиши, vendor E-Ink API, парольные PDF и завершение выбора файла через системный picker остаются непроверенными. В текущей реализации после показа первой страницы фоновая конвертация проходит все исходные страницы книги; отдельная эвристика, пропускающая преобразование, когда исходная страница удобнее, ещё не реализована.

Перед дальнейшей подготовкой к выпуску и расширением форматов необходимо уточнить:

1. Наличие и способ вызова vendor API полного обновления E-Ink-экрана.
2. Нужна ли обязательная поддержка DjVu, FB2, MOBI и CBZ в первой версии.
3. Какую область внешнего хранилища индексировать и какие каталоги исключать.
4. Приемлем ли установленный предел кеша 1 ГиБ и текущий размер debug APK.

Личная цель использования и отсутствие публикации в магазине приложений приняты как исходное допущение. Если план распространения изменится, требования по лицензиям нужно пересмотреть до выпуска.
